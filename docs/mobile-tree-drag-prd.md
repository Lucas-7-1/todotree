# TodoTree 手机端增量 PRD：原地展开与拖动整理

版本：评审稿 v1.1
日期：2026-09-26
状态：用户已确认，进入实现与验证。
适用基线：Android preview.3，当前手机项目页面。

## 1. 需求判断与设计结论

用户截图中的「贵阳之旅」已经具备清楚的任务列表，但「阿云朵仓」的子任务仍藏在下一页，顺序也缺少直接调整方式。

用户真正需要的是：看见一个项目完整的工作结构，直接拿起一个节点，把它放到应该属于的位置，包括移入、移出和调整先后顺序，然后继续执行。拖动的核心是操作节点关系，同级排序只是其中一种结果。树形展示用于理解关系，拖动用于整理关系；二者必须共用同一套真实任务数据。

本版推荐方案：**保留当前手机列表，项目内部默认使用可原地展开的树状大纲；长按任务标题直接拿起节点。拖到行间调整位置，停留在另一节点上移入其下，通过祖先落区移出当前父级。无需先进入整理模式。**

不采用需要横向拖动画布、缩放才能读懂的节点连线图。手机屏幕有限，优先保留任务名称、完成状态和操作空间。今天页继续保持平铺执行清单，项目页承担结构整理。

成功标准：用户不进入下一级页面，也能查看子任务；不用先点整理，就能直接拖动节点调整归属；能准确判断松手后任务会去哪；结构移动不会触发完成或归档。

## 2. 本轮范围

| 纳入本轮 | 保持现有逻辑或暂不纳入 |
| --- | --- |
| 项目内部树状展开、收起、展开状态记忆 | 今天页继续平铺，日历和 AI 复盘不重做 |
| 同级排序、项目内跨父节点移动 | 不做任意平移缩放的思维导图 |
| 直接拖动、移入／移出反馈、撤销、失败恢复 | 不做多指拖动或多节点同时拖动 |
| 深层节点可读性与聚焦入口 | 不改变默认为空、手动指定的四象限规则 |
| 与完成、划线保留、搞定、闭环的兼容 | 不修改用户已有完成时间、背景、备注和历史成果 |

顶级项目入口继续支持进入某个项目；入口列表可复用同级排序能力。本轮的树状展开和跨父级拖动重点在具体项目内部。跨项目移动通过「移动到…」实现，不要求用户拖着任务穿越多个页面。

## 3. 页面结构与点击规则

### 3.1 顶部

保留项目标题、返回、搜索、更多。进度行显示「直接子项：已完成 1 / 3」，右侧保留「项目详情」，不新增强制操作模式。首次使用时显示一次轻提示「长按任务可拖动，展开后可调整子任务」。交互入口触摸区域至少 44 × 44 CSS px。

「1 / 3」仅统计当前项目直接子项，包括划线保留及逻辑上已完成、仍属于该项目的已归档子项；删除项不计入。不能把父项和孙项混在同一个分母中。归档记录保留关系或历史归属，不能因为从主列表隐藏就丢失进度依据。

### 3.2 普通浏览状态

沿用当前列表：左侧完成框，中间标题，右侧更多；已完成且保留的节点右侧继续显示「搞定」。

有子项的任务，在标题下面显示独立的展开入口：「▸ 子任务 0 / 3」；点击后变为「▾ 子任务 0 / 3」，子任务紧接着显示在该任务下方。这里的符号为交互示意，实际使用图标组件。

| 用户操作 | 结果 |
| --- | --- |
| 点「子任务 x / y」或其展开箭头 | 当前页面原地展开、收起，不跳页 |
| 点项目内部的任务标题 | 打开任务详情，不改变展开状态 |
| 点完成框 | 沿用待确认 → 确认完成流程 |
| 点「搞定」 | 沿用主动归档该已完成分支的流程 |
| 更多 → 聚焦此项 | 进入以该节点为范围的页面；返回恢复原位置 |
| 更多 → 添加子任务 | 自动展开该节点，显示内联输入并聚焦 |

子项计数与展开入口必须区分：若该节点只有已归档子项、没有可展开行，显示「子项已归档 · 查看记录」，不能展示点击后什么都没有的展开箭头。

初次进入项目仅展示直接子项，下级默认收起。以后记忆每个项目的展开集合。只在用户选择「展开全部」时展开所有可展示层级，不因为保存、排序或恢复前台自动展开整棵树。

### 3.3 手机上的层级表达

- 每深入一级缩进 12px；延续现有最多 5 层规则。根项目在标题区时，其直接子项从本页第一级开始排列。
- 子项使用很淡的局部连接线；不为每一层叠加卡片背景或粗边框。
- 展开入口放在标题下方，不再增加一列按钮来压缩标题宽度。
- 普通状态不增加一列拖动把手：长按标题区域拖动，完成框、展开入口、更多与「搞定」各自独立，不触发拖动。
- 标题最多展示两行，点详情查看完整内容；320px 屏幕、最深层级时，标题可用宽度目标不低于约 150px，不出现页面横向滚动。
- 大字体导致空间不足时，辅助信息下移或换行；保留「聚焦此项」用于查看复杂子树，不强行继续压缩字体。
- 收起后，上级行尽量停留原位置；不跳回页面顶部。

以截图为例：点击「阿云朵仓」下方的子任务入口，直接在其下方显示现有子任务；「江湖烤鸡」和划线保留的「贵州省博物馆」仍在同一项目中。无需进入子页面再返回对照。

## 4. 直接拖动节点与结构调整

### 4.1 直接拿起，不强制进入整理模式

在任务标题区域长按约 300ms，触摸位移未超过约 8 CSS px 时，轻震一次并浮起节点卡片，此时开始拖动。长按成立前发生明显纵向位移，优先判定为滚动并取消本次拖动识别。参数需通过 Android 实机验证。

短按标题仍打开详情；完成框、展开入口、更多、搞定及输入框均不参与拖动手势。标题在任务行内的长按用于拖动，复制文字可在详情页完成。不得禁止整页正常滚动或文本编辑。

拖动开始后临时冻结其它完成、新增和多选动作，避免一根手指同时触发多个命令；松手或取消即恢复。不需要再点「完成整理」。若键盘正打开，先保存当前输入草稿并收起键盘，下一次长按再启动拖动，不能吞掉未保存内容。

多选状态、存在待确认完成操作、只读或服务尚未就绪时不启动拖动，并显示具体原因；不能悄悄清空已有勾选。划线保留、已经确认完成的节点仍允许拖动，待确认勾选不等于已完成。

### 4.2 三种明确的落点

| 操作意图 | 落点反馈 | 松手结果 |
| --- | --- | --- |
| 排在另一行之前或之后 | 蓝色插入线与该行所在层级对齐，显示目标父项与位置 | 以该行的父项为目标父项，插入对应位置 |
| 成为某任务的子项 | 在目标任务中部停留约 600ms 后，目标高亮并出现「移入『名称』，作为子任务」 | 插入目标的子项末尾；目标自动展开 |
| 移出当前父级、提升层级 | 拖动时出现祖先落区，例如「移出『阿云朵仓』 → 放到『贵阳之旅』下」 | 成为选定祖先的直接子项，默认排在原所属分支之后 |

停留时间为初始设计参数，实机验证后可调。只有稳定停留在目标中部才激活「移入」；快速划过、边缘自动滚动期间不激活。移出该区域立即取消激活。

跨层级插入线必须显式提示「移到『父项名』 · 第 n 项」，不能只靠线条位置推断。禁止仅凭手指向左、向右偏移就修改父级。

拖动开始后，在列表顶部显示固定的「移出到…」落区，列出当前父级以上、直到本项目根节点的祖先，最多受现有 5 层深度限制。每个落区明确显示目标名称；在狭窄屏幕中垂直排列，不能要求手指横向滚动寻找目标。空白处不是合法落区，向左轻扫也不自动改父级。移到当前项目之外或提升为独立顶级项目，使用「移动到…」中的明确目标；不通过拖出屏幕触发。

以截图为例，展开「阿云朵仓」后，长按其中一个子任务：拖到「江湖烤鸡」中部并稳定停留，可将它放进「江湖烤鸡」；拖到「贵阳之旅」祖先落区，可将它移出「阿云朵仓」，与其并列。拖动「阿云朵仓」自身时，其整个子树跟随移动。

收起的目标被激活为移入目标后，短暂展开以显示子项；继续拖到其中某个子项，可进入更深层级。只对稳定悬停的一个节点展开，不能连锁展开整棵树。取消拖动后恢复临时展开状态；成功后保留新父项展开。

同级排序、跨父级移动均无需成功后的额外确认弹窗；清晰预览与统一撤销承担防误触。松手到无效区域则回原位。

### 4.3 拖动整个分支

拖动有子项的节点，移动整个分支，绝不能只移动父行、把子项留在原处。

拖动卡片显示「任务名称 · 含 n 个子项」。n 为后代任务数量，不包含自身；归档历史不作为当前拖动卡片的可见任务计数。分支内子项相对顺序、完成状态、备注、截止日期保持不变。

拖动开始时，可临时将该分支后代从可见列表中折叠，用一张卡片表示；这是展示状态，不写入展开偏好。结束或取消后恢复展开状态，目标父项因接收新子项而展开。

### 4.4 反馈与取消

- 拖动卡片偏离手指约 24px，保持标题和目标文案可见；源位置留占位，不能瞬间消失。
- 有效位置显示插入线；无效位置显示明确原因；支持时用一次轻触觉反馈提示开始拖动与激活移入，不连续震动。
- 接近列表上下边缘时自动滚动，速度逐渐增加，不能整页跳动。
- 返回键、触摸取消、应用切到后台、手指移出可接受区域后松手：取消未提交拖动，恢复源位置。
- 落下后用 120–180ms 的短位移动效归位；不播放完成划线或消解动效。
- 每次有效松手独立提交一次结构变更；不要求用户再点击保存或退出整理。连续拖动时，前一次结构写入未确认前暂停下一次拖动，避免排序命令互相覆盖。

## 5. 无法精确拖动时的替代入口

每个可移动任务提供「移动到…」：项目／节点选择 → 目标父项预览 → 移动。与拖动使用同一套业务命令、校验和撤销记录。

该入口覆盖跨项目移动、长列表、深层目标以及读屏操作。另提供「上移一位」「下移一位」，便于不使用拖动手势的用户排序。

手动顺序下，划线保留项与未完成项共同遵循真实同级顺序，不能在每次渲染时强制把完成项挪到末尾，否则用户拖动后会立即跳回。首次启用时保留现有可见顺序作为起始顺序。

搜索、优先级排序、截止日期排序、分组或多选状态下不直接开放拖动，因为显示位置可能不是实际同级顺序。尝试长按时提供「在完整任务树中调整」入口；用户主动点击后进入手动顺序的完整当前项目树，定位该任务，并提供「返回原视图」。记录并恢复原查询与排序条件，不静默清空筛选。

「移动到…」在搜索结果中仍可使用，操作对象以稳定任务 ID 确定。

## 6. 与父子闭环的兼容：本轮必须守住的边界

**完成状态、归档状态、父子关系、显示顺序是四件事。移动只修改关系与顺序。**

| 场景 | 必须发生 | 不得发生 |
| --- | --- | --- |
| 同级换序 | 更新兄弟顺序 | 修改完成时间、触发闭环 |
| 将未完成子项移出 A，A 剩下的子项都已完成 | 重新计算 A 的进度；A 保持原完成状态，并显示「剩余子项已完成 · 确认完成」 | 把移动操作当成完成操作，自动消解 A |
| 移走 A 唯一子项 | A 成为无子项的普通未完成任务 | 因空集合“全部完成”而自动完成 |
| 把任务移入已完成或已归档节点 | 拒绝，并提示先恢复目标任务 | 悄悄重开目标、修改旧完成时间 |
| 移动划线保留的已完成分支 | 保留完成状态，按新位置展示；历史快照不变 | 再生成一条完成记录或重新统计为本期新成果 |
| 拖动已完成但保留的父节点 | 连同分支移动，仍划线保留 | 因移动自动执行「搞定」 |
| 通过确认完成使所有子项完成 | 沿用现有向上闭环检查 | 因本轮排序代码绕过原业务入口 |

“移出后剩余全完成”的处理是刻意的语义边界：结构整理不等于确认工作完成。用户点一次现有的「确认完成」后，才进入正常闭环流程；不是新增另一套完成机制。

正常完成规则继续保持：

1. 兄弟仍有未完成项时，已完成子分支在项目树中划线保留，提供「搞定」。
2. 最后一个未完成子项被确认完成时，重新检查直接父项并逐级向上判断；遇到仍有未完成子项的祖先就停止。
3. 自动完成的中间分支若仍处于未闭环上级中，保留划线，不直接整段消失。
4. 当前根项目满足闭环条件，或用户按既有流程确认完成整个父分支时，才整体归档并从活动项目页移除。
5. 拖动不新增完成确认、复盘或归档入口；已完成抽屉不会因为移动自动打开。

## 7. 数据、保存与撤销

### 7.1 最小数据变更

沿用任务 ID、parent_id、sort_order、完成／归档字段，不另建一套只存在于 UI 中的“树”。展开状态以「工作区 + 当前项目 ID + 节点 ID 集合」保存，作为界面偏好，与任务完成数据分开。

统一移动命令至少包含：操作 ID、源任务 ID、目标父 ID、相邻任务 ID 或插入位置、预期数据版本。业务层根据最新数据重新校验，不能直接信任拖动组件给出的数组下标。

同级移动仅更新必要排序字段。跨父级移动在一次事务中更新源节点 parent_id、对应根分组字段及受影响的排序字段；后代仍通过稳定 parent_id 关系跟随。按当前数据模型刷新必要的祖先索引与计数，不重写整库。

### 7.2 校验

- 不能移到自己或自己的任意后代下，包含收起、屏幕外的后代。
- 校验整个分支深度：目标深度 + 被移动分支高度不得超过现有 5 层限制，不能只检查源节点一层。
- 源或目标已删除／归档、只读状态、保存失败待恢复、版本冲突时禁止提交。
- 目标在拖动期间发生变化，松手时重新校验；失效则返回源位置并说明原因。
- 不继承目标父项的象限、日期或重复规则；不改变下一次重复任务的生成记录。
- 移动不产生 completed、archived 或 AI 自动生成事件。历史日历、报告中的完成时刻和当时路径不回写；当前任务路径可以随移动变化。

### 7.3 保存与撤销

拖动中只更新局部交互状态，不随手指移动写数据库。松手提交一次；保存完成再显示「已移动／已排序」。保存失败回滚展示，原数据保留，并允许重试。

若出现提交成功但响应丢失，沿用同一个操作 ID 查询／重试，避免重复移动；不生成新的业务操作冒充重试。

支持页面「撤销」与已有 Ctrl+Z。撤销只恢复该次操作修改的父级和顺序，不覆盖之后修改的标题、备注或完成状态。若原父项已删除或存在结构冲突，停止撤销并说明原因，不静默复活任务或改挂其它项目。

撤销跨父级移动后恢复原位置及正常展开状态；多次移动按已有撤销栈顺序逐次撤销。数据库提交与撤销均保留现有原子保存和恢复机制。

## 8. 性能与动效要求

- 以 parent_id → children 的索引构建可见树；不在每次触摸移动时全量递归、深拷贝任务库或写入存储。
- 只展开用户打开的分支；折叠后代不创建任务行 DOM。
- 可见行较多时按窗口渲染并保留少量预加载行。拖动自动滚动必须能够加载后续行，不能被“只显示前 50 条”截断目标范围。
- 拖动浮层使用 transform；目标变化时更新占位，不在每帧测量全树、改变全树高度。
- 已有完成消解动画保持独立；整理不触发归档动画、烟花或批量节点逐个退场。
- 减少动态效果设置开启时，取消过渡动画，保留明确落点和结果反馈。

验收目标：在记录硬件与系统版本的 Android 实机上，500 个活动节点、最多 5 层、展开约 100 行的场景中，开始拖动的可感知响应目标 ≤100ms；持续拖动不得出现明显冻结或按节点数量逐级播放动画。记录实际帧耗时和保存延迟，不能仅用桌面鼠标测试宣称手机顺滑。

## 10. 交付与评审口径

开发顺序：先完成可见树与点击语义，再接入统一移动命令和撤销，最后接拖动手势、自动滚动及实机性能验证。不能先做“能拖的视觉效果”，再临时补父子关系规则。

交付需要：正常树状列表、拖动同级排序、跨父级落点、移动失败、撤销、深层任务与键盘场景的截图／短录屏；节点身份、父子关系、完成历史的自动化回归记录；至少一台真实 Android 手机的触控验证结果。模拟器状态断言与截图、真实手机验收分别记录。

本稿待确认的产品决策只有三项：

1. 项目内部默认原地展开，标题打开详情，「聚焦此项」保留为次要入口。
2. 长按标题直接拖动；行间落点换序，目标中心停留后移入，祖先落区用于移出和提升层级。
3. 拖动可调整归属，但结构变化本身不触发自动闭环；自动闭环仍由确认完成触发。

用户确认此稿后，再开始代码修改。
