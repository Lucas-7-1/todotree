# TodoTree 手机端体验重构 PRD

版本：v1.0 · 待用户评审  
日期：2026-09-25  
适用范围：Android 手机端，兼顾窄屏 Web 视图  
交付阶段：需求与交互方案。用户确认后再实施，本文件不代表功能已完成。

## 1. 本次要解决什么

**让用户打开手机，立即看到今天要做的事情；用最少的操作记录、安排、完成一件事。**

手机端的主要使用场景是碎片时间查看与执行，而项目管理需要更完整的组织能力。界面应按使用频率分配空间：今日任务占主体，组织工具按需出现，历史记录进入二级页面。

本次重构围绕四个连续问题展开：

1. 我今天要做什么？
2. 临时想到一件事，怎样马上记下来？
3. 做完以后怎样确认、撤销，不破坏项目关系？
4. 需要调整计划或查历史时，去哪里？

### 1.1 截图中的实际问题

| 当前表现 | 对用户的影响 | 本版处理 |
|---|---|---|
| 搜索、筛选、分组、排序、象限速览、树视图等占据多层工具栏 | 进入页面先看到管理工具，任务被挤到下面 | 高频内容直接展示，低频工具进入筛选面板或更多菜单 |
| 树视图保留桌面表格宽度，出现横向滚动 | 看标题时看不到操作，手机单手操作困难 | 手机项目页改为逐层浏览，同层列表不横向滚动 |
| 底部新建区巨大，日期、优先级和重复按钮被挤成竖排 | 一次简单记录占据半屏，并遮挡已有任务 | 常驻单行快速录入；复杂属性进入新增面板 |
| 页面上多个新增、已完成和视图入口竞争注意力 | 不清楚该点哪个，路径冗长 | 每个页面只保留一个主要新增入口和一个明确的历史入口 |
| 空白页只说明“去全部任务加入今天” | 用户还要理解树结构才能开始安排 | 今日空态直接提供“安排已有任务”和“记一件事” |
| 只改善安全区、边距，保留桌面交互结构 | 不溢出也仍然难用 | 为手机建立独立的页面结构，复用业务与数据层 |

这些是截图能确认的体验问题。具体卡顿来源、组件重渲染及查询耗时需实施时测量，不能仅凭截图认定技术根因。

### 1.2 设计取舍

- 首屏优先展示任务标题、执行上下文和必要时间信息。
- 默认操作应能单手完成，不依赖悬停、右键、长距离拖拽或键盘快捷键。
- 复杂能力保留，但让用户在需要时打开。
- 同一任务只有一份业务数据；“今天”“项目”“四象限”是不同展示方式。
- 信息不足时仍允许记录；截止日期、象限、备注均不成为新增任务的前置条件。

## 2. 范围与信息架构

### 2.1 本版范围

**核心交付：** 今日主页、项目逐层浏览、快速录入、完成确认与历史查看的手机交互；其他主要页面同步消除桌面布局残留。

保留现有任务结构、手动象限分类、重复任务、完成记录、撤销和本地持久化能力。父子闭环以第 6 节规则为统一约束。

本版不增加云同步、AI 自动安排今日任务、AI 自动分配象限、全新提醒系统，也不全面重写桌面 UI。历史 PRD 中未涉及本次交互的能力保持原有范围。

### 2.2 底部导航

保留五个入口，避免把用户已在使用的重要能力藏掉：

| 入口 | 主要目的 | 默认展示 |
|---|---|---|
| 今天 | 执行今天的安排 | 当前待办列表 |
| 项目 | 组织全部任务与子任务 | 根层任务/项目列表 |
| 四象限 | 手动判断优先级 | 按象限切换的任务列表 |
| 复盘 | 生成与阅读工作总结 | 报告正文或生成入口 |
| 更多 | 设置、回收站、数据管理等 | 功能列表 |

原“任务”入口改名为“项目”，页面内补充简短说明“全部任务与项目”，包含独立任务，不能要求每项任务必须属于一个项目。

启动规则：

- 普通冷启动默认进入“今天”。
- 从后台恢复时保留当前页面、滚动位置和正在编辑的内容。
- 从明确的任务链接进入时优先打开指定任务。
- 切换底部导航时保留各页面位置；不因重新渲染重置导航。

## 3. 今日主页：让任务成为首屏主体

### 3.1 页面结构

从上到下只有四个主要区域：

| 区域 | 内容 | 交互 |
|---|---|---|
| 紧凑页头 | 今天、日期；右侧搜索、更多 | 点日期进入完成日历；更多内放筛选、排序、批量选择 |
| 一行进度 | “待办 6 · 已完成 2” | 已完成数字打开当日历史；不使用大统计卡 |
| 任务内容 | 今日任务、需重新安排的事项、折叠的今日完成记录 | 页面唯一主要纵向滚动区 |
| 快速录入 | “＋ 记一件今天要做的事” | 点击进入单行输入；可展开详细新增面板 |

移除今日首页上的大号“今日执行/完成日历”并排选项卡、常驻筛选条、分组下拉框、树状视图切换、大统计卡和常驻已完成侧边面板。

默认字号下，页头与进度区域合计目标不超过 112 逻辑像素，不含系统安全区。增大系统字体时允许自然增高，不能为达指标截断功能。

### 3.2 今日任务列表

默认列表标题为“今天要做”。每行展示：

- 完成操作区。
- 任务标题，默认最多两行；点击详情可看全文。
- 必要时展示一行项目路径，例如“贵州行 › 出行准备”。独立任务不显示空路径。
- 已设置时显示截止时间、象限或重复标识；未设置时不反复显示“未分类”“无日期”。

行内不摆放加子任务、分组、移动、复制、背景、备注等全部操作。点击标题区域进入任务详情，更多操作在详情或行菜单内。

象限标识必须同时支持文字辨认，不能只用一个红点表示“重要且紧急”。

**默认排序：** 有今日截止时间的任务按时间升序；只有今日截止日期的任务排在其后；仅手动安排今天的任务按安排顺序排列。同一优先级条件下保持稳定顺序。可在更多中切换为“按手动象限排序”，未分类置后。不得根据截止日期自动改写象限。

打开菜单、输入标题、待确认完成时，暂缓移动当前交互行，避免用户点击目标发生位移。

### 3.3 过期与未完成安排

今日主列表之外设置紧凑的“需要重新安排”区域，区分：

1. 已逾期：截止日期早于今天且仍未完成。
2. 之前安排但未完成：计划日期早于今天、未完成，且未在已逾期中展示。

有今日待办时该区域默认折叠并显示数量；没有今日待办但有这些事项时默认展开。每项支持“安排今天”“改截止日期”和详情查看。

同一任务在本页面只出现一行。已逾期但用户又安排今天的任务进入“今天要做”，保留“逾期”标签，不在下方重复。

不自动把昨日计划日期改为今天，不把多年积压任务全部展开占满首屏。

### 3.4 今日列表不是整棵树

手机今日页展示可处理的任务，不展示五层缩进树。父级路径提供上下文，完整关系在项目页查看。

对有未完成后代的父节点：

- 只有用户明确安排它，或它自身今天截止时，才作为“项目进度项”出现在今天。
- 展示“还有 N 项未完成”及“查看子任务”，不自动把后代全部加入今天。
- 父节点和子任务都符合今日条件时，可以同时存在，但父项显示进度样式，避免看起来是两件独立成果。
- 顶部待办数统计可直接执行的任务，项目进度项另标“另有 N 个项目待推进”，不把父子混算成工作量。
- 无子任务的独立任务正常作为可执行任务，不引入必须由用户维护的“任务/容器”新类型。

任务是否为项目进度项，以它实际拥有的有效子关系判断，包含已完成但保留关系的子节点；不能根据当前列表是否渲染了子节点判断。

### 3.5 三种空态

| 状态 | 文案与操作 |
|---|---|
| 没有任何任务 | “先记一件今天要做的事”，直接录入 |
| 有其他任务，但今天没有安排 | “今天还没有安排”，主操作“安排已有任务”，次操作“记一件事” |
| 今日任务已全部完成 | “今天的安排已完成”，显示完成数量和“查看今天做了什么”；仍可新增 |

筛选无结果显示“没有符合条件的任务 / 清除筛选”。数据加载失败显示加载错误与重试，不能伪装为空任务或“全部完成”。

## 4. 今天的进入与移出规则

### 4.1 数据含义

| 信息 | 含义 | 本版要求 |
|---|---|---|
| 今日计划日期 | 用户打算哪天执行 | 与截止日期独立；字段名可复用现有实现 |
| 截止日期/时间 | 最晚完成时间 | 允许为空；只有日期与具体时刻要区分 |
| 确认完成时间 | 用户确认本次完成的时间 | 用于完成日历与复盘 |
| 归档状态/时间 | 从活动项目结构中收起的状态 | 与确认完成分离 |
| 删除状态/时间 | 移入回收站的状态 | 不混同完成或归档 |

待确认完成是交互草稿，不提前写成正式完成记录。日期字段采用用户所在日期语义，完成事件保存时间戳；不得把所有“今天”都按 UTC 零点计算。

### 4.2 进入规则

| 操作或条件 | 是否进入今天 | 是否改变截止日期 |
|---|---|---|
| 在今日快速录入新任务 | 是，计划日期设为今天 | 否，默认仍为空 |
| 项目中点击“安排今天” | 是，只安排选中的节点 | 否 |
| 未完成任务今天截止 | 是，标注截止原因 | 否 |
| 重复任务今天的有效实例 | 按该实例计划日期/截止日期进入 | 不修改重复模板 |
| 仅设置为重要且紧急 | 不自动进入 | 否 |

按任务/实例稳定 ID 去重，不按标题去重。重复任务模板不作为每日待办反复显示。

### 4.3 移出规则：避免再出现“点了没用”

- 手动安排且没有今日截止条件：点击“取消今日安排”后移出今日主列表。
- 同时手动安排和今天截止：取消手动安排后仍保留，提示“已取消今日安排，仍因今天截止显示”。不显示错误的“已移出”。
- 仅因今天截止而出现：提供“调整截止日期”，不提供一个不会生效的“移出今天”。
- 已逾期：可以修改截止日期、完成，或折叠逾期区域；不能仅清空今日计划就宣称已解决逾期。
- 移出今日安排不删除任务、不改变象限、不移动项目。

跨午夜、应用恢复前台、系统时区改变时重新计算今日集合。编辑中的草稿保留，必要时提示“日期已变化”；不能悄悄把用户输入丢掉或改成另一天。

## 5. 快速记录与安排已有任务

### 5.1 快速新增

今日底部常驻一条约 48 逻辑像素高的入口。激活后仅展示标题输入与提交按钮，默认不展开多个属性。

1. 点击入口，键盘弹出，输入框始终位于键盘上方。
2. 输入标题，点击提交或键盘完成即可保存。
3. 今日页创建默认安排今天；没有选择项目则作为独立任务保存。
4. 保存成功后出现在正确列表中；保留录入焦点，便于连续记录，返回键可退出输入。

输入旁的“更多”打开新增面板，可设置所属项目、执行日期、截止日期、象限、重复与备注。标题草稿在两种输入方式间共享，不能重复创建。

手机不再同时显示顶部大号新建按钮和底部大型新增表单。所有按钮文字水平排版。

### 5.2 新增面板

- 默认先显示标题和少量常用属性，其他属性折叠。
- 键盘出现时转为可滚动的编辑页面/高面板，底部保存按钮保持可达。
- 空标题不能落库；只输入空格视为空。
- 中文输入法正在组词时，Enter 不提交任务。
- 保存中防止重复提交；失败保留标题与已选属性，提供明确重试。
- “已保存”只在持久化成功后显示。

### 5.3 安排已有任务

从今日空态或更多菜单进入任务选择页：支持标题与路径搜索，默认展示未完成任务，按项目浏览。选中集合保持累积，点击第二项不取消第一项。

底部操作为“安排今天（N）”。选择父节点只安排该节点，不隐式安排所有后代。批量操作一次提交，完成后返回今天。

多选复选框与“完成复选框”必须分属不同模式。选择模式有明确标题“选择任务”和退出按钮，不能点选择就完成。

## 6. 完成、划线保留与父子闭环

### 6.1 两个不同的结果

**从今日待办移走：** 任务已确认完成，今天不再要求用户执行它。  
**从项目树归档：** 根据父子关系判断，该分支可以从活动项目结构中收起。

这两个结果独立判断。完成一个分支，允许它离开今日待办，但不能因此把还有未完成兄弟节点的上级项目整体消解掉。

### 6.2 手机完成路径

普通单任务只需两次明确操作：

1. 点击完成框：该行轻微划线，进入“待确认”，原位显示“确认”“取消”。
2. 点击确认：持久化成功后播放退出动画，离开今日待办；底部提示“已完成 · 撤销”。

不跳转到详情，不要求填写成果说明，不打开已完成抽屉。成果说明可在详情或历史中补充。

这里的 double check 指两步确认，不依赖系统识别快速双击手势。点标题仍是看详情，不能意外完成。

连续勾选多项时：每项待确认状态保留，底部出现“确认完成 N 项 / 取消”；单项确认与批量确认共用相同业务入口。批量模式启用后可将各行确认入口收为状态提示，减少重复按钮。

待确认期间切换页面，已有非空确认草稿在会话中保留；彻底关闭应用后未确认项仍为未完成，不制造完成记录。不能超时自动确认。

### 6.3 父子闭环判定表

| 情况 | 业务结果 | 今日页 | 项目页 |
|---|---|---|---|
| 一个叶子完成，兄弟仍未完成 | 该叶子完成，上级未完成 | 叶子离开待办 | 叶子划线保留，显示“搞定” |
| 分支 A 的全部子项完成，但 A 的兄弟 B 未完成 | A 自动判定完成，上级仍未完成 | A 及已完成项不再作为待办 | A 分支划线保留，默认折叠，显示“搞定” |
| 根项目的全部有效子项完成，逐级检查均满足 | 根项目完成，整棵项目归档 | 对应待办移出 | 整组退出，进入已完成 |
| 用户主动确认完成一个父节点 | 该父节点及全部未完成后代完成，再向上判断 | 对应项移出 | 若更上级仍有未完成兄弟则划线保留，否则随根项目归档 |
| 用户点已完成分支旁“搞定” | 提前归档该已完成分支 | 不新增一次完成 | 分支退出，上级其余任务继续展示 |

自动向上判断必须检查完整业务子关系，不能只检查屏幕当前可见项，也不能只检查过滤后的数组。删除项不作为待完成阻塞项；已归档的完成子项仍作为已完成关系参与判断。没有有效子项的节点不能因“空数组全部成立”而自动完成。

检查自当前节点逐级向上进行，直到遇到仍有未完成子项的祖先。中途完成的分支保留，不把它当作自动归档的根。

### 6.4 父级手动完成与批量选择

- 待确认时直接显示影响范围，例如“确认完成此项及 4 项子任务”。这一步就是二次确认，不再叠第三层弹窗。
- 同时选中父与子时按 ID 合并影响范围，同一节点只变更一次、只记录一次本次完成事件。
- 已完成子任务保持原完成时间，不改成父节点今天完成的时间。
- 上级自动闭环记录标记为“由子项完成触发”，不能在复盘中当成额外独立交付重复累计。
- 重复任务只完成本次实例，未来实例不被一并完成。

### 6.5 撤销与历史

完成提示中的“撤销”和全局撤销调用同一事务回滚能力。手机用户不需要键盘；外接键盘时保留 Ctrl/Cmd+Z，输入框内优先撤销文本编辑。

一次撤销恢复该次操作影响的节点、祖先状态、归档状态和完成事件有效性，不撤销之前独立完成的兄弟节点。若后续修改导致冲突，提示并进入恢复流程，不能覆盖较新的修改。

短提示可在约 6 秒后消失；提示消失不等于历史不可恢复。完成日历与已完成记录仍提供恢复入口。

已完成面板只由用户主动打开。在活动任务上开始完成确认时，关闭会遮挡操作的完成面板；完成后只更新计数，不自动弹回。

## 7. 项目页：逐层进入，直接操作当前层

### 7.1 默认呈现

根层展示独立任务和项目；有子任务的项目行显示进度和进入箭头。点击项目进入它的直接子列表，页头显示返回、项目标题与更多。

点击叶子任务打开详情。项目本身的详情由页头“详情”进入。完整路径在详情中可查看，不让五层面包屑挤占列表宽度。

手机端本版不把桌面树形表格作为默认或并列视图。保留相同父子结构和最大深度约束，通过逐层导航表达；未来需要树概览时再单独评估。

返回上层恢复原滚动位置；当前项目被归档时返回最近仍有效的上层，并显示结果提示。

### 7.2 子任务新增

当前项目页列表末尾有“＋ 添加子任务”。点击即出现当前层空白输入行并聚焦，不要求该项目已经有其他子任务。

- 空白行是本地草稿，保存前不参与进度与闭环计算。
- 保存后自动插入当前父 ID 下，不能依赖是否已经存在 children 数组或展开图标。
- 当前节点从零个子任务变为一个子任务时，展示与入口同步更新。
- 点击取消或空白失焦可收起空草稿；非空失焦保留草稿，不静默删除。
- 当前节点达到现有最大深度时禁用新增后代并解释原因，不能点了无响应。
- 在项目中新增默认不安排今天、不设置截止时间、不继承父级象限；用户可显式选择“同时安排今天”。

已完成保留分支若需要继续新增，先明确执行“重新打开并添加”，重新计算必要祖先状态。不能悄悄让已完成父项拥有未完成子项。

### 7.3 搜索、筛选与多选

页头保留搜索与更多。搜索页明确当前范围“此项目 / 全部任务”；筛选面板集中放象限、截止日期、重复、完成状态等条件。

只在有筛选条件时展示紧凑条件提示，支持一键清除。排序选择作用于当前同级列表，不修改父子关系。

多选通过更多菜单“选择任务”进入，长按可作为快捷方式但不作为唯一入口。批量工具优先包含安排今天、修改象限、完成；删除放更多并沿用回收站机制。

批量操作需展示选中数量；父子同时选中时，说明去重后的实际影响数量。

## 8. 其他页面同步适配

### 8.1 完成日历与历史

- 从今日日期或“查看今天做了什么”进入独立二级页面。
- 上方月历展示各日完成数量，点击日期，下方展示当天时间线；返回恢复今日滚动位置。
- 日历按确认完成时间归日，保留原项目路径快照，任务改名或项目迁移后仍能理解历史。
- 自动父级闭环单独标注，不与叶子完成数混在一起；已提前完成的子任务不因父级后来完成而重算到今天。
- 对撤销/恢复明确更新有效完成结果，保留可追溯记录，不虚增完成次数。
- 按月份查询摘要，按日期分页查详情；不一次加载所有历史正文。

### 8.2 四象限

手机默认使用“未分类、重要且紧急、重要不紧急、紧急不重要、不重要不紧急”的分组切换，选中后展示完整宽度列表。

入口可以用两行紧凑分组按钮，不强求五个长标签挤在一行。2×2 概览仅作为可选摘要；不在窄屏中放四条很窄的任务列。

分类通过任务菜单/详情选择，移动后给出反馈与撤销。拖拽不作为手机必须操作。象限仍默认空，父子独立。

### 8.3 工作复盘

手机优先展示报告正文，周期、项目、模板与附加要求放在顶部紧凑入口打开的设置面板。报告历史为独立页面，诊断信息折叠到详情，不能同时并列正文、历史栏和已完成抽屉。

保留已有手动生成与提示词配置能力。信息缺少时提供基于已知事实的基础总结及可选补充提示；不得因为未填背景而把正文变成拒绝生成说明。此处沿用既有生成规则，不新增 AI 自动推断任务优先级。

### 8.4 任务详情

手机使用独立详情页或接近全屏的面板，按标题、状态/时间、所属项目、背景/成果/备注组织。主操作固定且可达，低频复制、移动、删除收进更多。

返回优先关闭键盘、再退出编辑层、再返回来源页面。未保存的有效输入需要保留或明确提示，不允许直接消失。

## 9. 视觉与布局标准

| 项目 | 要求 |
|---|---|
| 基准验证宽度 | 360、393、430 逻辑像素；补测横屏与系统字体放大 |
| 页面边距 | 常规 16 逻辑像素，紧凑区域可 12 |
| 正文与任务标题 | 基准 16，辅助信息通常 12–14；跟随系统字号，不锁死缩放 |
| 点击目标 | 主要交互至少 44×44 逻辑像素；图标可以更小但热区不能更小 |
| 任务行 | 高度随两行标题、元信息增长；不为放满屏幕压成小字 |
| 内容优先级 | 标题最强；时间/必要标签其次；路径更弱；不满屏彩色胶囊 |
| 固定区域 | 底部导航与单行录入适度固定，不叠加大型悬浮工具栏 |
| 键盘 | 显示时隐藏底部导航，输入区跟随可用视口；键盘收起再恢复 |
| 安全区 | 明确一个布局层负责顶部和底部避让，避免重复加 padding |
| 横向布局 | 页面本体不得横向滚动；不允许按钮中文逐字竖排 |
| 面板 | 手机同一时刻只有一个主要浮层；不并列多个桌面侧栏 |

在 393×852 逻辑像素、默认字体、普通两行以内测试任务下，进入今天应能直接看到至少 5 条任务；此为测试样例目标，不适用于放大字体或超长内容时强行压缩。

系统字体放大到 130% 和 200% 时，允许行高、工具栏换行，保证操作仍可访问。不得通过缩小字号、隐藏任务标题或禁用缩放满足布局。

## 10. 动效、性能与程序精简

### 10.1 完成动效

确认持久化成功后，当前可见任务行轻微侧移并淡出，目标时长 160–220ms；其余行一次平滑补位。

- 整组归档只动画当前可见分支容器，不遍历所有后代逐个播放。
- 划线可以轻量过渡，不使用粒子消解、大范围模糊或多层阴影动画。
- 动画不是业务提交条件，后台切换或动画中断不能造成半完成。
- 业务提交后可保留短暂的退出视图快照播放动画；不能因此把完成项重新算入待办。
- 支持减少动态效果偏好，降级为短淡出或直接更新。
- 失败时保留原行和输入，明确显示未成功，不播放假成功消失。

### 10.2 实施原则

建立手机页面组件与样式边界，复用任务查询、完成、归档、撤销、持久化等业务服务。避免继续用大量全局 nth-child、强制宽度或 overflow 隐藏遮住问题。

不为今天、项目和象限维护三份任务副本。使用稳定 ID 和统一派生查询，更新受影响的节点与必要祖先。

输入、滚动、动画期间不全量序列化工作区、不扫描所有完成历史、不触发整个应用刷新。先测量实际热点，再对长列表、历史分页、计算缓存做有依据的优化。

虚拟列表只用于确有长度压力的列表；编辑中的行要保留焦点，不能滚动后丢失草稿。小列表无需为“架构完整”增加复杂缓存和状态系统。

### 10.3 目标与测试口径

以下是验收目标，不是当前性能结论。实施开始时记录同一台 Android 测试设备、系统版本和基线数据，优化后用同一条件复测。

| 场景 | 目标 |
|---|---|
| 点击新增、选择、完成预确认 | 可见反馈通常在 100ms 内 |
| 本地列表切换 | 已加载数据下通常在 200ms 内出现内容 |
| 完成动画 | 基线设备接近 60fps；不得因一个分支包含大量不可见节点明显停顿 |
| 输入标题 | 不随项目总量增加出现明显逐字卡顿 |
| 大数据样例 | 10,000 任务、50,000 完成/操作记录，查询与分页范围可控 |
| 内存与监听 | 连续切换页面和开关面板 50 次，无持续增长的重复监听/定时器 |

记录耗时与卡顿轨迹。无法达到目标时说明具体瓶颈、设备和降级方案，不能只写“已优化”。

### 10.4 交给实施 Agent 的优化指令

> 先梳理手机端完成一次“查看今天—新增—确认完成—撤销”的数据和渲染路径，测量当前耗时，再实施本 PRD。为手机建立适合触屏的页面结构，复用现有业务服务与持久化。合并重复状态和重复事件入口，删除确认不再使用的旧手机布局补丁与监听；不要以减少代码行数为目标重写稳定模块。优先减少全量扫描、全量写盘和无关组件刷新，长历史按范围查询，整组归档只处理可见动画。保持父子闭环、事务、恢复和数据兼容性。完成后提交前后对比截图、真实设备交互录像、性能基线与验证结果；没有实际验证的项目明确标注未验证。

## 11. 数据兼容、状态与异常

### 11.1 状态分工

- 持久化业务状态：任务、父子关系、计划日期、截止日期、完成/归档事件、重复实例。
- 会话交互状态：选中集合、待确认集合、输入草稿、打开面板。
- 可保存的界面偏好：排序选择、必要筛选、页面滚动位置；不能覆盖普通冷启动进入今天的规则。

选中集合、待确认集合、正式完成状态必须分开，不能用一个 selectedTaskId 承担全部职责。

### 11.2 数据保护

- 复用当前正式数据存储，不因 UI 改版切换到临时缓存或新增第二套数据库。
- 如需字段迁移，先备份、版本化迁移、验证，失败时保留旧数据，不以空库覆盖。
- 更新安装需要保持应用身份和签名连续性；验收使用覆盖安装，不要求用户卸载旧版。
- 新增、批量完成和父子归档按既有原子提交机制实现；重复点击使用稳定操作 ID 防重复。
- 加载失败、只读、写入失败各有真实状态说明。“已保存”不能在异步提交前出现。
- 已完成面板、日历和复盘读取同一完成事实；撤销后同步失效，不出现跨页面互相矛盾。

### 11.3 生命周期

应用前后台切换、旋转、键盘变化、页面跳转不得重复提交任务或丢弃有效草稿。异步结果返回时核对当前任务/查询版本，旧搜索结果不能覆盖新结果。

手机系统返回键遵循当前层级；有输入时先处理键盘与编辑层。不要让一次返回同时关闭键盘、丢失草稿并退出应用。

## 13. 实施顺序与评审决定

用户确认后按以下顺序推进，每阶段能独立验证：

1. 固定今日集合、完成与归档边界及数据回归样例。
2. 重建今日主页、快速新增和已有任务安排流程。
3. 重建项目逐层浏览、子任务新增及完成确认交互。
4. 适配日历、象限、复盘、详情，完成性能与真机视觉验收。

本版建议用户重点确认以下四项产品决定：

| 决定 | 本版默认方案 |
|---|---|
| 手机首页要保留多少管理工具 | 今天优先，搜索和更多之外不常驻桌面工具栏 |
| 手机项目层级怎样看 | 逐层进入；今日使用平铺执行列表，不默认展示缩小树表 |
| 完成后何时消失 | 今日确认后移出；项目依据祖先闭环规则划线保留或归档 |
| 昨日没做完如何处理 | 明确列为需重新安排，不自动把所有旧任务改成今日计划 |

本文件评审通过前，不继续修改应用代码或发布新版安装包。
