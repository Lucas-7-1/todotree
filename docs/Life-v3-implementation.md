# TodoTree Life v3 实施与验证

本分支基于 `gpt-6-android-v1` 的 `9af2ecb`。本次落实已确认 PRD 的 P0/P1 改进与 P2 可用健康流程，沿用现有任务、手帐及媒体存储，不合并到主分支。

## 可以使用的流程

- 根页面「待办 / 手帐 / 健康」一键切换；待办底栏保留今天、项目、四象限、复盘四项，设置与备份放在页面更多。
- 今日关联训练显示「开始训练」。加入本次安排具有稳定 ID，重复点击不会重复创建；任务完成只关闭安排，不虚构训练。训练保存和待办更新通过持久化 outbox 分两次可靠提交，失败显示重试入口；自动每轮最多处理一次，累计最多三次，不无限重试。
- 手帐事件树按事件时间或输入时间排序，支持方向切换。深层/首个子细节可直接新增；长按专用把手拖入事件、移出为独立事件，支持边缘自动滚动、禁放自身/后代、撤销；拖动期间提示条不遮挡落点。时间排序只改变展示，移动不改历史时间。
- 美食及其他消费标签显示金额输入；金额为整数分，未知留空、零表示零消费；账单/明细/独立消费与个人支付分开。保留照片轮播、封面、地点及可打开的 HTTP(S) 分享链接。
- 健康按日历查看实际记录；体重数值/标尺、kg/斤、前次候选值和真实趋势；饮食名称/克重/每100g能量与来源快照，未知也可保存；跨夜睡眠按结束日归属，重叠汇总去重。实际记录可编辑、移入回收站、恢复，删除支持按钮和 Ctrl+Z。
- 常用训练模板可改动作、组数、次数、负重口径、休息。模板可长按或菜单加入今天，可创建一次/每日/每周计划、暂停后续安排。预先查看未来安排不会导致当天漏建待办。
- 训练支持直接完成本组与可选手动计次动画。已计6次后快捷完成10次目标，结果是10；目标到达只提交一次；休息暂停/继续、加30秒、跳过，结束后等待用户开始下一组；最后一组没有多余休息。提前结束只记录实际做过部分，可选择是否关闭本次安排。
- 草稿与训练进度在本机保存。Android 使用单调时钟和本机版本化休息提醒，应用内恢复不依赖逐帧写入。重新开机后计时环境变化需显式确认；通知/准时提醒需用户授权，无法开启时提供系统计时器入口，不误称锁屏一定准时。
- 默认工作 AI 复盘排除健康关联任务、后代及其历史事件。手帐和健康数据库不会隐式拼入工作报告。

## 数据与升级

任务继续使用原 workspace；手帐继续使用 journal.db 和原媒体目录。健康使用独立 health.db：WAL、事务化增量提交、记录版本校验、幂等操作确认、删除标记、每日写入前恢复点（保留14份）。没有“读取失败后写空数据库”的路径。Web 使用 IndexedDB；浏览器刷新保留同一会话的编辑权，不再误判成旧标签占用。

待办备份、手帐含照片备份、健康 JSON 备份由各自入口导出；当前不是三域一键全量备份，也不自动云同步。健康备份导入保留同 ID 的本机冲突记录。

**签名与数据：** debug 预览包的 applicationId 为 `com.lucas.todotree.lifev3`，可以与现有应用并存，避免未知旧签名导致必须卸载旧应用。它不会自动读取旧应用的私有目录，需要从旧应用导出并在预览包导入。正式 release 包保持原 `com.lucas.todotree`，覆盖升级必须用原签名；环境未提供原私钥时仅生成未签名 release，不能承诺它可直接覆盖安装。不要为安装预览包删除旧版或清除数据。

## 验证

`npm test` 包括既有父子闭环、持久化和 Android bridge 回归，加上手帐时间/消费口径及健康状态机/存储回归。健康测试包括串行提交、丢失确认后同操作重试、错误读取不清空、备份冲突不覆盖。

浏览器真实页面测试：

```sh
node tests/journal-browser-smoke.cjs
node tests/journal-tree-browser.cjs
node tests/health-browser.cjs
```

涵盖首个子/孙节点、拖动/撤销、相册/封面、照片重启保留、三模式、健康快记/草稿、今日训练关联、计次/休息恢复、编辑/删除/撤销、备份及360/393/430px无横向溢出。

84 项自动化测试通过，三组浏览器页面回归通过，包括草稿落盘后刷新恢复，以及旧草稿不能覆盖已更新记录。Android 原生编译与 release lint 通过；新增 `HealthStoreTest` 用于验证事务回滚、幂等确认、数据库重新打开和删除恢复。原生测试包已编译，当前本机没有可用模拟器，尚未执行这些原生用例；GitHub Actions 配置了模拟器执行。浏览器与编译结果不等于真机锁屏、系统重启、键盘、不同系统字体与省电策略全部验收通过，仍需安装预览包按 PRD 实机验证。

## 尚未宣称完成的后续阶段

- 当前可追溯在线食品来源为 USDA Foundation / SR Legacy（显式查询，15分钟小型缓存），另支持用户包装/配方数值。公共 DEMO_KEY 仅供试用且可能限流；查询失败可以继续保存未知热量。中国菜、外卖、品牌食品完整覆盖、正式查询 Key 管理与多源授权是 P3 后续，不把示例热量当生产数据。
- 沿用现有 AI 请求快照、提示词与报告校验能力；本次增加健康隐私隔离。完整报告人工编辑、跨模式回顾等未在本次冒称新增完成。
- 高德/美团/口碑官方店铺检索/导入、通用待办闹钟、系统日历、IM/办公渠道提醒属于 P4：需要实际平台授权、配置和真机验证。当前只有地点文字/分享链接以及训练休息提醒，没有虚假的已接入按钮。
- 大规模真机帧率、启动耗时及录屏尚需实际设备测量。代码已拆分健康懒加载、手帐分页与索引，计时只刷新局部展示，实际动作才做增量保存；不凭编译结果声称性能指标全部达标。
