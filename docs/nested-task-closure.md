# 嵌套子任务、划线保留与分支闭环

基于 main 的 `6576c70`，本次只修改嵌套新增及完成/归档行为。

## 行为

| 操作 | 结果 |
| --- | --- |
| 点击任意任务右侧 + | 原位出现输入框，绑定该节点的真实 ID；支持最多 5 层 |
| Enter | 保存并继续输入；创建失败保留文字；Esc 取消草稿 |
| 在已完成但仍保留的子任务下新增 | 新任务及该父链重新进入进行中；新增及重新开启合并为一个撤销步骤 |
| 确认完成一个子任务，兄弟任务仍未完成 | 划线保留，显示「搞定」；根分类与普通父节点规则一致 |
| 点击「搞定」 | 仅归档当前已完成项/分支；不改完成时间，不重复生成完成记录，不完成未完成的兄弟任务 |
| 最后一个子任务确认完成 | 自动闭环父节点；向上逐层检查，直到遇到未完成的兄弟任务；归档闭环分支及其所有后代 |
| 手动确认完成父任务 | 完成全部有效后代，归档该分支；符合条件的祖先同步闭环 |
| Ctrl+Z / 页面撤销 | 恢复该次操作涉及的状态及归档标记；撤销单独归档后重新显示划线任务 |
| 恢复已归档子任务 | 同时重新开启已完成的祖先，避免出现进行中子任务被已归档父节点挡住 |

已归档项在「已完成」中保留。划线保留项本身已经完成，因此也保留完成记录；归档只是显示状态，不是第二次完成。已删除任务不参与闭环判定。自动重复任务的新实例会重新开启所属父链。

## 本次修正的代码问题

1. 在已完成节点下创建任务时，旧创建逻辑没有重新开启已完成父链，新增任务可能落入不可见分支。现在所有新增入口共用 `insertTaskNode`。
2. 草稿的 blur 与 + 的 click 会连续发生，旧处理函数读取上一轮渲染的草稿状态时可能误判「已有草稿」而直接返回。改为基于最新状态更新；创建失败不清空输入。
3. + 放在标题的截断容器内。移到独立操作位，并提供键盘可访问名称，避免长标题挤占操作入口。
4. 旧保留条件把 `root_bucket=categories` 排除；但根任务正是使用这个字段。移除该特殊处理。
5. `status=done` 同时用于完成事实和隐藏判定，无法表达「已完成但保留」和「主动归档」。新增可选 `archived_at`，兼容旧任务数据。
6. 完成、恢复、父节点弹窗原先有多段相似状态修改；现在共用 `taskLifecycle.ts`，并将归档字段纳入增量撤销。
7. Toast 中的撤销回调可能持有操作前的任务数组。改为从最新任务引用执行撤销/重做。

## 桌面发行

仓库原有 `TodoTree.exe` 内嵌旧版 HTML；源码更改不会自动更新该 EXE。发布时需重新执行：

```sh
npm ci
npm test
npm run build
node bundle-singlefile.mjs
```

然后在 Windows PowerShell 编译：

```powershell
& "C:\Windows\Microsoft.NET\Framework64\v4.0.30319\csc.exe" /target:winexe /r:System.Web.Extensions.dll /out:TodoTree.exe /resource:dist\TodoTree_一键直达.html desktop-host\Program.cs desktop-host\DurableWorkspace.cs
```

打包后用新版 EXE 验证本页行为。请勿仅替换源码就将旧 EXE 标为已更新。
